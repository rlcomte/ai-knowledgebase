<Definition term={"AI Suitability"}>
AI suitability is the decision process for determining whether a task should use an AI model at all, and if so where it should sit in the workflow. A suitable use case has useful signal in available data or context, clear success criteria, tolerable and detectable errors, recovery paths, responsible data use and a human or system boundary for high-impact decisions.
</Definition>

## Why It Matters

AI suitability asks whether the task benefits from pattern recognition, generation or flexible reasoning and whether errors are detectable, tolerable and recoverable.

The point is not whether AI can produce something plausible. The point is whether probabilistic behaviour can be responsibly embedded in the workflow with the right evidence, controls and human authority.

<EngineeringMode>
AI suitability is an architecture and risk decision. Design should separate tasks needing judgment, language or perception from tasks needing exact rules. Build work may prototype the uncertain part while preserving deterministic paths for critical calculations. Operations compare model value against cost, latency and error recovery. The risk is using AI because it is available rather than because the task benefits from probabilistic behavior.
</EngineeringMode>

<RealExample>
Meeting summarization is often AI-suitable because transcripts are messy, summaries are reviewable and users can tolerate some editing. Payroll calculation is usually not suitable for generative AI because the rules are explicit, mistakes are costly and deterministic software can provide more reliable, auditable results.
</RealExample>
