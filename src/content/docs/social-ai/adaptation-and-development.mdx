<Definition term={"Adaptation and Development"}>
Adaptation is the process by which experience changes future behavior. Development is adaptation organized over time into governed memory, policy, skill and identity change.
</Definition>

## Why It Matters

Adaptation is often used too loosely. A social agent can adapt within the current context, through persistent memory, through behavioral policy, through skill revision or through model-weight changes. These mechanisms have different risk profiles.

For long-lived social agents, prefer adaptation through context, memory, policy and skills before model weights. These layers are easier to inspect, explain, version, reverse and govern. Model adaptation can be useful, but it raises harder problems around consent, auditability, cross-user leakage, catastrophic forgetting and identity drift.

<figure class="concept-explainer-image">
  <img src={adaptationTargets.src} alt="Three adaptation targets in social agents: user model, self model and relationship model." loading="lazy" decoding="async" />
</figure>

Social adaptation also has multiple targets. Experience may update the user model, the agent's self model or the relationship model. Keeping these separate prevents personalization from being mistaken for relational development.

<EngineeringMode>
Use explicit adaptation records. State what evidence triggered the change, what layer changed, who authorized it, how confidence was assigned and how the change can be reverted. Consequential adaptations should be negotiated with the user rather than silently inferred.
</EngineeringMode>

<EvaluationCheck>
Evaluate whether adaptation improves usefulness without reducing corrigibility, increasing dependency or causing identity drift.
</EvaluationCheck>

<RealExample>
If an agent notices that a user often asks for conceptual diagrams, it can first adapt context for the current session, then propose a memory, and only later update a reusable explanation skill if the pattern is validated.
</RealExample>
