<Definition term={"Evals and Error Analysis"}>
Evals are repeatable measurements that test whether an AI system performs acceptably on representative tasks, edge cases and risk scenarios. Error analysis is the structured inspection of failures to identify patterns, root causes and improvement actions, such as better instructions, retrieval, data cleaning, tool design, guardrails or human review.
</Definition>

## Why It Matters

An eval is a structured test of AI-system behaviour using representative inputs, expected properties and scoring methods. Scores may be deterministic, model-based or human. Evals should measure the application, not just the underlying model.

Evaluation-driven development states desired behaviour as evaluable criteria, measures a baseline, analyses errors, changes one thing and checks regressions. Evals play a role analogous to tests, while accounting for probabilistic output.

Error analysis means inspecting failures, clustering them into meaningful categories and deciding which change is most likely to improve the system. Aggregate scores without qualitative error analysis rarely indicate what to build next.

<EngineeringMode>
Evals turn AI behavior into an engineering feedback system. Architecture should make runs reproducible and connect prompts, models, data and traces to scores. Design must define what good, unsafe and unacceptable look like. Build work creates datasets, graders and review workflows. Operations track regressions after releases. The risk is relying on aggregate scores without inspecting the concrete failures that explain what to fix.
</EngineeringMode>

<RealExample>
SWE-bench made coding-agent evaluation concrete by using real GitHub issues and checking whether generated patches pass repository tests. The useful lesson is procedural:

1. Define the task set.
2. Run the agent.
3. Score against objective checks.
4. Inspect failures before changing the system.
</RealExample>
