<Definition term={"Tool Calling and MCP"}>
Tool calling lets a model request a structured operation, such as a database lookup, calculation, file action or API call, while the surrounding application validates arguments, executes the operation and returns results. MCP, the Model Context Protocol, standardises how hosts connect models to external tools and data sources so integrations can be reasoned about as explicit capability boundaries.
</Definition>

## Why It Matters

Tool calling allows a model to request a defined operation, such as querying a database, running code or calling an API. The application, not the model, must validate arguments, permissions, results and side effects.

Model Context Protocol is an open protocol for connecting AI applications to tools, data sources and reusable capabilities through standard interfaces. MCP improves interoperability; it does not remove the need for authentication, authorisation, validation and trust boundaries.

<EngineeringMode>
Tool calling changes architecture from text generation to controlled action. Interfaces need typed inputs, permissions, timeouts, retries and audit logs. Product design must make tool authority visible when actions affect users or data. Build work includes validation, idempotency and error handling. Operations track failed calls and side effects. The risk is letting a fluent model trigger powerful tools without engineering-grade contracts.
</EngineeringMode>

<RealExample>
A coding agent fixing a bug should not merely describe a patch. A tool-aware harness can let it search the repository, read the failing test, edit the file and rerun the command. MCP generalizes this pattern by giving agents structured, permissioned access to external systems through explicit tool contracts.
</RealExample>
