<Definition term={"Grounding and RAG"}>
Grounding is the practice of constraining model output with task-relevant evidence from trusted sources, live system state or authoritative tools. Retrieval-augmented generation is a common grounding pattern in which the system retrieves candidate passages or records, injects selected context into the model call and evaluates whether answers are supported by that evidence.
</Definition>

## Why It Matters

Grounding connects model output to trusted, task-relevant sources or system state. It reduces unsupported generation and enables answers that reflect current or private information.

Retrieval-augmented generation is a pattern in which relevant information is retrieved and supplied to the model during inference. A RAG pipeline typically covers ingestion, parsing, chunking, metadata, indexing, retrieval, reranking, context assembly, generation and citation.

<EngineeringMode>
Grounding makes evidence flow a first-class architecture concern. Engineers must design ingestion, retrieval, ranking, context assembly, citation and permission checks. Product design should let users inspect evidence and challenge unsupported answers. Build work includes evals for answer support, freshness and refusal behavior. Operations monitor retrieval misses, stale content and hallucinated citations. The risk is labeling a feature RAG while leaving evidence quality unmeasured.
</EngineeringMode>

<RealExample>
Microsoft Copilot for Microsoft 365 is a recognizable grounding case. A useful answer may need the user’s documents, meetings and email, not just model memory. The system must retrieve relevant evidence, pass it into the model and keep enough provenance for the user to verify the answer.
</RealExample>
