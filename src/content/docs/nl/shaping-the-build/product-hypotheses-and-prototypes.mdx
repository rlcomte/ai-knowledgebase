<Definition term={"Producthypotheses en prototypes"}>
A product hypothesis is a falsifiable statement about a user problem, proposed AI behaviour, expected outcome and measurable evidence. A prototype is a deliberately limited artifact used to test that hypothesis before committing to a full build. In AI work, prototypes should test model behaviour, user trust, error recovery, data availability and workflow fit, not only interface appeal.
</Definition>

## Waarom dit ertoe doet

A product hypothesis is a falsifiable statement linking an intervention to an expected user or organisational outcome. It provides a reason to build a test rather than a full product.

A prototype is a low-cost representation used to learn about desirability, usability, feasibility or AI behaviour. A vertical slice is a small end-to-end implementation that crosses interface, logic, model, data and operations. It exposes system risks earlier than isolated component demos.

<EngineeringMode>
Hypotheses and prototypes keep AI engineering empirical. Architecture should support thin slices, instrumentation and safe experiments before platform commitments. Design must express what user behavior would prove value. Build work creates prototypes that test the riskiest assumption, not the prettiest demo. Operations compare evidence against adoption, quality and cost. The risk is scaling a convincing prototype before learning whether it solves the real problem.
</EngineeringMode>

<EvaluationCheck>

<RealExample>
Duolingo Max is a clear product-hypothesis case. The team can test whether AI roleplay and answer explanations help learners practice more often or understand mistakes faster. A prototype should measure learning behavior and user trust before the feature is expanded across languages, levels or subscription tiers.
</RealExample>
