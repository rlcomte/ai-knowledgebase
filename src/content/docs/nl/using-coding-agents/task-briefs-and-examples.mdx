<Definition term={"Taakbriefings en voorbeelden"}>
Een taakbriefing is een compacte specificatie voor een agentsessie: doel, scope, relevante bestanden, randvoorwaarden, toegestane acties, niet-doelen, acceptatiecriteria en vereist bewijs. Goede voorbeelden tonen zowel de gewenste output als de grenzen van een acceptabele implementatie. Dat helpt agents brede herschrijvingen, verborgen aannames en niet-geverifieerde claims over afronding te vermijden.
</Definition>

## Waarom dit ertoe doet

Een bruikbare taakbriefing scheidt uitkomst, gebruikersbehoefte, scope, randvoorwaarden, acceptatiecriteria en verificatie. Zo krijgt de agent genoeg context om lokale keuzes te maken, terwijl de mens de regie houdt over intentie en risico.

```markdown
# Uitkomst
Voeg bronverwijzingen toe aan de antwoordweergave.

# Gebruikersbehoefte
Gebruikers moeten de bron achter een door AI gegenereerde bewering kunnen inspecteren.

# Scope
- API-responseschema en webantwoordcomponent
- Alleen de bestaande retrieval-pipeline

# Randvoorwaarden
- Achterwaartse compatibiliteit behouden
- Geen nieuwe dependency in productie
- Maak interne opslag-ID’s niet zichtbaar

# Acceptatiecriteria
- Elke gegronde bewering kan één of meer bronlinks tonen
- Ontbrekende bronverwijzingen worden gracieus afgehandeld
- Contract- en UI-tests slagen
- Toegankelijkheid is via het toetsenbord gecontroleerd

# Verificatie
- Voer uit: npm test
- Voer uit: npm run lint
- Render en inspecteer de antwoordweergave
```

<EngineeringMode>
Taakbriefings zijn requirements engineering voor agentwerk. Architectuur- en ontwerpbeperkingen moeten worden vastgelegd voordat de agent wijzigingen aanbrengt. Bouwtaken profiteren van voorbeelden, doelbestanden, acceptatiecriteria en validatiecommando’s. Operations hergebruikt goede briefings voor terugkerend werk en vergelijkt uitkomsten. Het risico is vage doelen geven en vervolgens de agent de schuld geven omdat die optimaliseert tegen onuitgesproken randvoorwaarden.
</EngineeringMode>

<RealExample>
Een sterke taakbriefing voor een AI coding agent is voldoende specifiek om te testen. Bijvoorbeeld: “Voeg CSV-export toe voor gefilterde facturen, behoud de huidige permissies, neem leegtoestand-gedrag op en voer npm test uit.” De agent kan dan de juiste bestanden inspecteren en bewijs leveren in plaats van te gissen naar de intentie.
</RealExample>
