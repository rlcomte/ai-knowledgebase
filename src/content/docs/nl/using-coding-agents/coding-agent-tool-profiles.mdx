<Definition term={"Toolprofielen voor coding agents"}>
Een toolprofiel voor een coding agent beschrijft hoe een specifiek product dezelfde engineering-controlepunten implementeert: projectinstructies, laden van context, bestands- en shelltools, permissies, herbruikbare workflows, evaluatiebewijs, subagents en orkestratie. Het profiel helpt teams een agent te kiezen en te configureren op basis van workflowfit in plaats van enkel merkvoorkeur of benchmarkclaims.
</Definition>

## Gedeelde principes

De blijvende vaardigheid is niet het uit je hoofd leren van één productinterface. Het is leren hoe je elke coding agent vormt tot een gecontroleerde engineeringwerker.

| Principe | Wat te definiëren | Bewijs dat het werkt |
|---|---|---|
| Persistente projectinstructies | Repository‑richtlijnen zoals `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `DESIGN.md`, architectuurregels en codestandaarden. | De agent volgt lokale conventies zonder herhaaldelijk te hoeven worden geprompt. |
| Contextgrenzen | Welke bestanden, mappen, tickets, designdocumenten en logs de agent moet inspecteren voordat er actie wordt ondernomen. | De agent citeert of gebruikt het juiste lokale bewijs en vermijdt irrelevante ruis. |
| Tool- en permissiebeleid | Welke tools mogen lezen, bewerken, commando’s uitvoeren, het netwerk benaderen of externe systemen aanroepen. | Riskante acties vereisen goedkeuring; secrets en destructieve operaties blijven onder controle. |
| Herbruikbare workflows | Skills, commando’s, regels, prompts, hooks of gedocumenteerde playbooks voor herhaald werk. | Reviews, migraties, releases en debugging‑taken volgen een herhaalbaar pad. |
| Evals en verificatie | Tests, checks, statische analyse, criteria voor handmatige review en taakspecifiek acceptatiebewijs. | Voltooiing wordt ondersteund door commando‑uitvoer, screenshots, diffs of evaluatieregistraties. |
| Gebruik van meerdere agents | Heldere beslissingen over wanneer verkenning, implementatie, review of onderzoek over agents wordt opgesplitst. | Parallel werk verkort de doorlooptijd zonder conflicterende bewerkingen of niet‑verifieerbare samenvattingen te veroorzaken. |
| Orkestratie en overdracht | Een leidende agent of een mens wijst werk toe, verzamelt resultaten, lost conflicten op en beslist wanneer te stoppen. | Overdrachten bevatten scope, aangeraakte bestanden, onopgeloste risico’s en verificatiestatus. |

## Codex

Codex is op zijn sterkst wanneer de repository expliciet maakt hoe werk uitgevoerd moet worden en welk bewijs moet worden geleverd.

| Principe | Implementatie in Codex |
|---|---|
| Persistente projectinstructies | Codex leest gelaagde `AGENTS.md`‑bestanden voordat het werk start. Globale richtlijnen kunnen in de Codex‑homedirectory staan, repositoryrichtlijnen in de projectroot, en geneste richtlijnen kunnen bredere regels overschrijven voor gespecialiseerde mappen. Gebruik dit voor buildcommando’s, reviewregels, designsystem‑beperkingen, beveiligingsgrenzen en repoconventies. |
| Contextgrenzen | Codex werkt vanuit de huidige workspace, de geladen instructieketen, de user prompt en gekoppelde tools. Houd taakomschrijvingen concreet: noem de doelbestanden, het verwachte gedrag, de beperkingen en verificatiecommando’s. Gebruik `DESIGN.md` als projectartefact wanneer UI‑ of contentontwerpbeslissingen de implementatie moeten sturen. |
| Tool- en permissiebeleid | Codex biedt gecontroleerde tools aan zoals bestandszoekopdracht, bestandsbewerking, shellcommando’s, MCP‑connectors en browser/site‑tools afhankelijk van de omgeving. Behandel goedkeuringsbeleid, sandboxing, netwerktoegang en secrets als onderdeel van het taakontwerp, niet als bijzaak. |
| Herbruikbare workflows | Codex ondersteunt skills: herbruikbare `SKILL.md`‑workflows met optionele referenties, scripts en assets. Gebruik skills voor herhaalde procedures zoals PR‑review, releasechecks, documentconversie, Figma‑handoff of site‑deployment. |
| Evals en verificatie | Codex kan repositorychecks uitvoeren en kan worden aangestuurd om het bewijs te rapporteren. Paar Codex met CI, lokale tests, contentvalidators, browserscreenshots en reviewrubrics voor agent‑output. Voor agentworkflows gebouwd met OpenAI API’s, gebruik evals om taaksucces, veiligheid en regressierisico te meten. |
| Gebruik van meerdere agents | Codex ondersteunt subagent‑workflows voor onafhankelijk werk. Gebruik ze voor verkenning, review, testonderzoek of parallelle implementatie alleen wanneer het werk schoon te scheiden is. Reken op hogere tokenkosten en eis een leidende thread om outputs samen te brengen. |
| Orkestratie en overdracht | Codex kan optreden als de leidende werker in een lokale repo of als deelnemer in een bredere workflow. Goede overdrachten bevatten geladen instructies, gewijzigde bestanden, uitgevoerde commando’s, mislukte pogingen, resterende risico’s en of een menselijke beslissing nog vereist is. |

Gebruik Codex wanneer je een repository‑bewuste agent wilt die direct in een gecontroleerde workspace kan werken, `AGENTS.md` volgt, skills gebruikt, lokale tools kan aanroepen en verifieerbare diffs produceert.

## Claude Code

Claude Code is op zijn sterkst wanneer projectgeheugen, slash‑command‑achtige workflows, hooks en subagents doelbewust georganiseerd zijn.

| Principe | Implementatie in Claude Code |
|---|---|
| Persistente projectinstructies | Claude Code gebruikt `CLAUDE.md` als het belangrijkste projectgeheugenbestand. De officiële documentatie positioneert het voor codestandaarden, architectuurbeslissingen, voorkeurbibliotheken en reviewchecklists. Gebruikers‑ en projectniveau‑regels kunnen ook worden gebruikt om persoonlijke voorkeuren te scheiden van teambeleid. |
| Contextgrenzen | Claude Code werkt vanuit de terminal, het huidige project, geselecteerde bestanden, prompts en gekoppelde tools. Gebruik `CLAUDE.md` en gescope regels om te definiëren wat de agent eerst moet lezen, hoe `DESIGN.md` te interpreteren, en welke mappen of commando’s gezaghebbend zijn. |
| Tool- en permissiebeleid | Claude Code heeft CLI‑flags en instellingen voor toegestane en niet‑toegestane tools, permissiemodi en extra directories. Gebruik deze controles om read‑only review, implementatie, automatisering en hoogrisico‑operaties te scheiden. |
| Herbruikbare workflows | Claude Code ondersteunt skills voor deelbare herhaalbare workflows, plus hooks die shellcommando’s vóór of na acties draaien. Gebruik hooks voor formattering, linting of policychecks waar automatisering consistent moet zijn. |
| Evals en verificatie | Claude Code kan commando’s uitvoeren en via de CLI gescript worden. Verificatie moet nog steeds worden geëxternaliseerd naar tests, CI, linters, typechecks, securityscans en reviewchecklists zodat het resultaat niet alleen een conversatieclaim is. |
| Gebruik van meerdere agents | Claude Code ondersteunt meerdere agents, aangepaste subagents en achtergrondagents. Aangepaste subagents zijn Markdown‑bestanden met YAML‑frontmatter, inclusief een naam, beschrijving, toollijst, model en system prompt. Gebruik dit voor rollen zoals verkenner, reviewer, testonderzoeker of migratieplanner. |
| Orkestratie en overdracht | Claude Code kan parallelle agents coördineren of worden aangestuurd via aangepaste workflows. De leidende agent of mens moet outputs samenvoegen, bewerkingsconflicten oplossen en beslissen of het resultaat uitleverbaar is. |

Gebruik Claude Code wanneer je een terminal‑gecentreerde agent wilt met sterke geheugenbestanden, CLI‑automatisering, hooks, aangepaste subagents en flexibele scripting.

## Gemini Code Assist

Het huidige enterprise‑codingproduct van Google is Gemini Code Assist Standard en Enterprise. In agent‑modus gedraagt het zich meer als een gecontroleerde IDE‑agent dan als een volledig open‑eindige lokale terminalwerker.

| Principe | Implementatie in Gemini Code Assist |
|---|---|
| Persistente projectinstructies | De agent‑modus van Gemini Code Assist ondersteunt contextbestanden met de naam `GEMINI.md`. Deze kunnen globaal, voor een project of voor een component/subdirectory worden gescope. Standaard chat ondersteunt ook regels in IDE‑instellingen, al merkt Google op dat het gedrag van sommige regels verschilt in agent‑modus. |
| Contextgrenzen | Gemini Code Assist gebruikt IDE‑workspacecontext, geselecteerde bestanden/mappen, toolantwoorden en contextbestanden. Enterprise code customization kan geïndexeerde repositorycontext toevoegen uit private codebases, afhankelijk van productconfiguratie en limieten. |
| Tool- en permissiebeleid | Agent‑modus gebruikt ingebouwde tools zoals bestandlezen/-schrijven, grep, symboolgebruik en Git afhankelijk van IDE‑ondersteuning. Muterende bestandssysteem‑ of resourceacties vereisen toestemming tenzij anders geconfigureerd. |
| Herbruikbare workflows | Gemini Code Assist stelt in de aangehaalde documentatie geen Codex‑ of Claude‑achtige native "skills"‑bestandsformaat bloot. Gebruik `GEMINI.md`, IDE‑regels, gedocumenteerde prompts, MCP‑servers en repository‑playbooks om herbruikbare workflows te benaderen. |
| Evals en verificatie | Behandel verificatie als repository‑eigendom: tests, typechecks, CI, reviewchecklists en acceptatiecriteria. Gemini kan helpen werk in de IDE uit te voeren of te interpreteren, maar duurzame evaluatie moet buiten het chattranscript leven. |
| Gebruik van meerdere agents | De agent‑modus van Gemini Code Assist ondersteunt meerstapswerk en MCP‑tools. De aangehaalde Code Assist‑documentatie definieert geen eersteklas systeem voor aangepaste subagents vergelijkbaar met Codex‑subagents of Claude Code‑subagents. Gebruik externe orkestratie of splits werk handmatig wanneer meerdere agents nodig zijn. |
| Orkestratie en overdracht | Gebruik Gemini Code Assist als een in de IDE verblijvende werker. Voor grotere workflows, houd orkestratie in tickets, designdocumenten, CI en menselijke review, en gebruik Gemini vervolgens voor gescope implementatie-, uitleg- en reparatietaken. |

Gebruik Gemini Code Assist wanneer je team in ondersteunde IDE’s werkt en Google‑beheerde code‑assistentie, workspacecontext, enterprise‑repository‑aanpassing en MCP‑verbonden agent‑modus wil.

## Selectierichtlijnen

Kies de agent op basis van workflowfit, niet op merk.

| Workflowbehoefte | Sterke match |
|---|---|
| Repositorybewerkingen met expliciete projectinstructies, skills en lokaal bewijs | Codex |
| Terminalautomatisering, aangepaste subagents, hooks en scriptbare workflows | Claude Code |
| IDE‑geïntegreerde assistentie met Google Cloud‑enterprise‑controles en geïndexeerde repositorycontext | Gemini Code Assist |
| Hoogrisicoproductiewijziging | Elke agent alleen met smalle permissies, menselijke goedkeuring en onafhankelijke verificatie |
| Brede verkenning over veel bestanden | Codex of Claude Code met subagents; Gemini Code Assist wanneer het werk van nature IDE‑gescope is |

<EngineeringMode>
Toolprofielen vertalen productverschillen naar engineeringgevolgen. Architectuurteams moeten contextladen, toegang tot tools, permissies, subagents, hooks en vastlegging van bewijs vergelijken. Ontwerpwerk definieert welke workflows elke tool mag ondersteunen. Build‑werk valideert claims met echte repositorytaken. Operaties volgen leverancierswijzigingen en beleidsfit. Het risico is een coding agent kiezen op merk of benchmark in plaats van op workflowcontrole.
</EngineeringMode>

<EvaluationCheck>
Vraag voor elke agent: welk instructiebestand is geladen, welke context is geïnspecteerd, welke tools waren toegestaan, welk bewijs bewijst voltooiing, en wie is eigenaar van de eindbeslissing?
</EvaluationCheck>

<RealExample>
Een team dat Codex, Claude Code en Gemini Code Assist vergelijkt kan dezelfde bugfix‑taak via elk tool laten lopen. De nuttige vergelijking is niet merkvoorkeur: controleer welke instructies geladen waren, welke bestanden zijn gewijzigd, welke permissies werden gevraagd, welke tests draaiden en hoe duidelijk elk tool het resterende risico uitlegde.
</RealExample>
