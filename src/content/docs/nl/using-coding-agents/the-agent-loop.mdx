<Definition term={"De agent loop"}>
De agent loop is de herhaalde regelcyclus waarin een agent de huidige taakstatus observeert, redeneert over de volgende stap, via een tool of bericht een actie uitvoert, het resultaat inspecteert en beslist of hij doorgaat, bijstuurt of stopt. Betrouwbare loops hebben expliciete stopvoorwaarden, begrensde tooltoegang, voortgangscontroles en verificatie, zodat de agent niet afdwaalt, oneindig blijft loopen of optimaliseert voor een plausibel verhaal in plaats van afgerond werk.
</Definition>

## Waarom dit ertoe doet

De agent loop is de terugkerende cyclus: context observeren, redeneren over de volgende stap, handelen via een tool, het resultaat inspecteren, het plan bijwerken en stoppen of doorgaan. De exacte interne implementatie verschilt per product.

Bewijsgebaseerde afronding betekent succes uitroepen op basis van geïnspecteerde diffs, geslaagde checks, gerenderde output of ander concreet bewijs, niet op het eigen vertrouwen van de agent. De loop is alleen nuttig wanneer waarnemingen betrouwbaar zijn en stopvoorwaarden duidelijk.

<EngineeringMode>
De agent loop maakt verificatie onderdeel van de actie. Architectuur moet tools blootleggen om de toestand te lezen, bestanden te wijzigen en resultaten te observeren. Het ontwerp moet laten zien wanneer de agent iterereert, geblokkeerd is of om toestemming vraagt. Build‑werk hangt af van snelle tests en inspecteerbare traces. Operations houden loops in de gaten die zonder voortgang blijven herhalen. Het risico is de agent door laten gaan met handelen nadat bewijs aangeeft dat het plan fout is.
</EngineeringMode>

<RealExample>
Een coding agent die een falende checkout‑test repareert, demonstreert de loop. Hij leest de fout, inspecteert de betalingscode, past een validatie‑branch aan, draait de test opnieuw en gebruikt de nieuwe output om de volgende zet te bepalen. De loop stopt pas wanneer verificatie de wijziging ondersteunt.
</RealExample>
