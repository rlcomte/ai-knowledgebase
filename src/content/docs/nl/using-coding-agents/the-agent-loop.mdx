<Definition term={"De agent loop"}>
The agent loop is the repeated control cycle in which an agent observes the current task state, reasons about the next step, performs an action through a tool or message, inspects the result and decides whether to continue, revise or stop. Reliable loops need explicit stopping conditions, bounded tool access, progress checks and verification so the agent does not drift, loop indefinitely or optimise for plausible narration instead of completed work.
</Definition>

## Waarom dit ertoe doet

The agent loop is the recurring cycle: observe context, reason about the next step, act through a tool, inspect the result, update the plan and stop or continue. The exact internal implementation differs by product.

Evidence-based completion means declaring success based on inspected diffs, passing checks, rendered output or other concrete evidence, not the agent's own confidence. The loop is only useful when observations are reliable and stopping conditions are clear.

<EngineeringMode>
The agent loop makes verification part of action. Architecture should expose tools for reading state, changing files and observing results. Design must show when the agent is iterating, blocked or asking for authority. Build work depends on fast tests and inspectable traces. Operations watch loops that repeat without progress. The risk is letting the agent continue acting after evidence says the plan is wrong.
</EngineeringMode>

<RealExample>
A coding agent fixing a failing checkout test demonstrates the loop. It reads the failure, inspects the payment code, edits a validation branch, reruns the test and uses the new output to decide the next move. The loop stops only when verification supports the change.
</RealExample>
