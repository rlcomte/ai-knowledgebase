<Definition term={"Technical debt, documentatie en teamwork"}>
Technical debt is the future cost created when a system becomes harder to understand, change or operate than it needs to be. Documentation preserves decisions, contracts and operational knowledge; teamwork defines how people coordinate design, implementation, review and ownership. In AI projects these disciplines keep rapid agent-generated changes from becoming opaque, duplicated or unsafe.
</Definition>

## Waarom dit ertoe doet

Technical debt is the future cost created by expedient decisions. Agent-generated duplication, unnecessary dependencies and undocumented abstractions can accumulate debt unusually quickly.

Documentation and decision records explain how to use the system and why consequential decisions were made. Architecture decision records preserve context that code alone cannot express.

Collaboration and review depend on shared standards, code review, issue tracking, ownership and constructive challenge. Human review should focus on risk and system intent, not only formatting.

<EngineeringMode>
AI systems create technical debt in prompts, eval sets, data assumptions, model choices and undocumented workflows. Architecture needs decision records and ownership boundaries. Design needs shared language for review and escalation. Build work should update docs when behavior changes. Operations need runbooks and incident learning. The risk is a system that still works today but cannot be safely changed by the team tomorrow.
</EngineeringMode>

<RealExample>
A team that repeatedly patches prompts without recording why will accumulate AI technical debt. Later engineers cannot tell which examples prevent regressions, which model assumptions changed or which failures were accepted. Documentation, decision records and shared eval results keep the system maintainable.
</RealExample>
