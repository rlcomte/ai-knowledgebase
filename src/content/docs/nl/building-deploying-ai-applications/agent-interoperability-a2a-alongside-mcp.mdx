<Definition term={"Agentinteroperabiliteit: A2A naast MCP"}>
Agent2Agent (A2A) is een open protocol voor communicatie tussen onafhankelijke, mogelijk opaque agent-systemen. Het vult MCP aan: MCP standaardiseert hoe een agent-runtime tools en data bereikt, terwijl A2A standaardiseert hoe een agent een andere agent ontdekt, een taak delegeert en voortgang of resultaat-artifacts ontvangt over runtime- of leveranciersgrenzen heen.
</Definition>

## Waarom dit ertoe doet

Lokaal toolgebruik en samenwerking tussen remote agents zijn verschillende grenzen. Behandel een remote agent als een externe dienst met gedeclareerde capaciteiten, een eigen identiteit en bevoegdheid, expliciete taakstatus en een observeerbaar contract—niet als een functieaanroep die toevallig tekst teruggeeft.

A2A modelleert de interactie rond vier kernobjecten:

- **Agent Card:** een machineleesbare beschrijving van identiteit, endpoint, skills, ondersteunde interfaces en authenticatievereisten van de remote agent. Zo kan capability discovery vóór delegatie plaatsvinden.
- **Task:** de stateful eenheid van werk met lifecycle, identifier en optionele context. Een handoff krijgt zo een duurzame plek voor status, annulering en herstel.
- **Message:** een communicatieronde om een task te starten, verduidelijking te vragen of verdere input te geven. Het is niet de betrouwbare container voor taakuitvoer.
- **Artifact:** een taakresultaat, zoals tekst, gestructureerde data of een bestand, opgebouwd uit getypeerde onderdelen. Artifacts horen in het omliggende systeem provenance- en validatiemetadata te krijgen.

<EngineeringMode>
Behandel A2A als een grens van gedistribueerde systemen. Los de Agent Card op en valideer die, authenticeer de caller, autoriseer de gevraagde skill en geef een correlation ID plus de gebruikers- of servicebevoegdheid door die de delegatie mogelijk maakte. Plaats time-outs, begrensde retries, idempotency keys, annulering, concurrency-limieten, backpressure en rate limiting in de harness. Houd MCP-servers achter de eigen machtigingsgrens van de remote agent; een A2A-handoff mag niet automatisch alle tools erven die de caller kan gebruiken.
</EngineeringMode>

## MCP en A2A samen

Een orchestrerende agent kan MCP gebruiken om lokale context te lezen of een gecontroleerde tool aan te roepen, en daarna A2A gebruiken om werk aan een specialist te delegeren. De specialist kan intern zijn eigen MCP-servers gebruiken. De grens moet duidelijk maken welke agent verantwoordelijk is voor elke actie, welke principal die autoriseerde, welke tools beschikbaar waren en welke artifacts terugkwamen.

Voor end-to-end tracing geef je trace- en spancontext door via de A2A-request, task-updates, MCP-aanroepen en artifact-overdracht. Leg de versie van de Agent Card, task- en context-ID's, message-ID's, skill, bevoegdheid, beleidsbesluiten, retries, latentie, statusovergangen en artifact-hashes vast. Redigeer secrets en gevoelige payloads, maar bewaar genoeg gestructureerd bewijs om te reconstrueren wie wat vroeg, waar het draaide en waarom het resultaat is geaccepteerd.

Streaming en push-notificaties zijn nuttig voor langlopende of eventgedreven workflows, maar voegen bezorgings- en beveiligingsrisico's toe. Authenticeer webhook-requests, valideer de verwachte task-ID en bron, maak notification handling idempotent, bescherm tegen replay en SSRF en herstel gemiste events door taskstatus opnieuw te lezen. Verwar een live stream niet met duurzame bezorging.

<EvaluationCheck>
Vraag of een test of trace kan aantonen dat een agent via een geldige capability-declaratie is gevonden, met minimale bevoegdheid is aangeroepen, zonder dubbele neveneffecten is geretried en via elke runtimegrens aan het eind-artifact is gekoppeld.
</EvaluationCheck>

<RealExample>
Een incidentcoördinator ontdekt via de Agent Card een specialist voor loganalyse en delegeert een onderzoek. De specialist gebruikt MCP om het observability-systeem te bevragen, streamt statusupdates, retourneert een ondertekend findings-artifact en gebruikt dezelfde trace-ID als de coördinator. Een mens keurt elke remediatie-agent goed voordat een aparte A2A-task productie mag wijzigen.
</RealExample>
